Kloud Kart - Customer spending report: before and after
=======================================================

Date: 2026-11-27
Environment: Windows 11 laptop, Docker Desktop; PostgreSQL 18.7 container (8 vCPU, 16 GB visible),
shared_buffers=128MB, work_mem=4MB, max_connections=500, TimeZone=UTC; CPython 3.15.2,
psycopg2-binary 2.9.13.
Database: kloudkart_audit, a scratch database created empty and loaded with course/schema.sql
and course/load.sql (categories 94, products 4,023, customers 40,420, orders 159,384,
order_items 336,559, inventory_log 282,352). A separate database was used so the existing
kloudkart_lab database was not reset. Schema, data and scripts are the same as in the README's
Compose setup, which names the database kloudkart_lab.

Command: psql -f sql/benchmarks/report_benchmark.sql
Report date (p_as_of): 2026-08-31 23:59:59, the end of the extract.
Timings are EXPLAIN ANALYZE execution times on a warm cache. All variants use
the shared is_sale_status() rule.

The laptop was busier for this run than for an earlier recording the same
morning (shipped report median 1,375 ms then, 1,635 ms here). Absolute times
vary with machine load; compare variants within one run.

Summary
-------
A  Naive report (one correlated lookup per figure, per customer, per month),
   no index:              34,028 ms for 100 customers
                          (about 13,750 s, roughly 4 hours, for 40,420 customers,
                          extrapolated linearly; not run in full)
B  Same naive report with an index on orders(customer_id):
                          52 ms for 100 customers (about 21 s extrapolated)
C  Set-based report (solution 02), all 40,420 customers, 485,040 rows,
   no extra index:        median 1,635 ms (1,528 - 1,838 ms over 5 runs)
D  C plus a partial covering index on completed orders:
                          median 1,459 ms (1,436 - 1,718 ms over 5 runs), 11% faster
E  C with work_mem raised to 64MB so sorts stay in memory:
                          median 1,669 ms (1,563 - 1,867 ms over 5 runs), not faster

Decision: ship C. D saves about 180 ms on a weekly report but adds an index
that every order insert must maintain during a flash sale. E shows the
remaining time is the window and aggregate work over 485,040 output rows,
not disk sorting, so no further tuning was pursued.

A is a reconstruction of the usual hand-written shape of this report;
Adwoa's actual query was not supplied.
